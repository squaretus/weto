# Дизайн-система Weto

Канон визуального языка приложения. Источник — утверждённый мокап направления «Сегменты».
Любой новый экран, компонент или правка собираются из токенов и компонентов этого документа;
сырые значения (hex, размеры шрифта, радиусы) в местах использования запрещены.

## Принципы

1. **Статус читается за долю секунды.** Цвет щита и заголовок статуса — первое, что видит глаз
   в попапе менюбара. Всё остальное вторично.
2. **Цвет никогда не единственный носитель смысла.** Рядом с цветным элементом всегда есть текст:
   зелёный щит — «На страже», красный — «Цели завершены».
3. **Группировка карточками.** Экран — это набор карточек с заголовками-капсами, а не сплошной
   список строк. Внутри карточки строки разделены волосяной линией.
4. **Одно первичное действие на группу.** Фиолетовая заливка — только у главного действия
   (например, «Добавить»); остальное — приглушённые кнопки.
5. **Плотно, но не тесно.** Шаг сетки 3 pt, вертикальный ритм строк 6 pt, воздух между
   карточками 9 pt.

## Токены

### Цвет

Две темы, обе рисуются вручную и проверяются отдельно. Выбор темы — явный (Тёмная / Светлая),
следования системной теме нет.

| Токен | Роль | Тёмная | Светлая |
|---|---|---|---|
| `shell` | фон окна и попапа | `#17161D` | `#E7E4F1` |
| `card` | фон карточки | `#201F28` | `#FFFFFF` |
| `sunk` | утопленные поверхности: поля ввода, дорожка сегментов | `#2A2833` | `#EEEBFA` |
| `line` | границы карточек и разделители строк | `rgba(255,255,255,.08)` | `rgba(28,20,60,.16)` |
| `sunkLine` | граница утопленных поверхностей | прозрачная | `rgba(28,20,60,.10)` |
| `ink` | основной текст | `#F4F2FB` | `#16102C` |
| `dim` | вторичный текст, значения | `rgba(244,242,251,.66)` | `rgba(22,16,44,.72)` |
| `faint` | подписи, капсы, неактивные иконки | `rgba(244,242,251,.40)` | `rgba(22,16,44,.52)` |
| `violet` | акцент: первичные кнопки, активный сегмент | `#8B7BFF` | `#6244F0` |
| `green` | статус «на страже» | `#46D09B` | `#0E8A5B` |
| `amber` | статус «сервис недоступен» | `#F2B544` | `#9D6A09` |
| `red` | статус «цели завершены», деструктивные действия | `#FF6B81` | `#D43A53` |
| `close` | кнопка закрытия окна | `#FF5F56` | `#FF5F56` |

Светлые оттенки статусов и акцента специально затемнены относительно тёмных: на белой карточке
исходные значения не добирают 4.5:1.

### Тень и глубина

| Токен | Тёмная | Светлая |
|---|---|---|
| `panelShadow` | `0 20 48 rgba(20,10,50,.32)` | `0 20 48 rgba(20,10,50,.32)` |
| `cardShadow` | нет | `0 1 2 rgba(24,14,60,.08)`, `0 8 20 rgba(24,14,60,.07)` |

В тёмной теме карточка отделяется от фона цветом, в светлой — тенью. Других уровней глубины нет:
модальные окна системные (`NSAlert`), собственных оверлеев не рисуем.

### Типографика

Базовый шрифт — системный (SF Pro). Мокап нарисован в Instrument Sans; переносить веб-шрифт
в бандл не стали, чтобы не терять Dynamic Type и покрытие кириллицы.

| Роль | Размер | Начертание | Цвет | Где |
|---|---|---|---|---|
| Статус | 15 | semibold | цвет статуса | заголовок попапа |
| Название пункта | 13 | medium | `ink` | строки настроек, имя цели |
| Значение | 13 | regular | `dim` | правая часть строки, `Happ ▾` |
| Подпись | 12 | regular | `faint` | путь к цели, версия |
| Данные | 12 | regular, tabular | `dim` / ключи `faint` | строка IP и источников |
| Капс карточки | 11 | semibold, uppercase, трекинг +0.1em | `faint` | заголовок карточки |
| Диагностика | 11 | regular, tabular | `faint` | нижняя строка записи журнала |
| Кнопка | 13 | semibold | по типу кнопки | все кнопки-пилюли |
| Сегмент | 12 | medium | `dim`, активный — белый | табы и переключатели |

Цифры в данных, счётчиках и датах — всегда `monospacedDigit`, иначе значения дёргаются
при обновлении.

### Сетка, радиусы, размеры

Шаг — 3 pt.

| Токен | Значение | Применение |
|---|---|---|
| `space1` | 3 | зазор внутри дорожки сегментов |
| `space2` | 6 | вертикальный паддинг строки |
| `space3` | 9 | между карточками, отступ под капсом |
| `space4` | 12 | внутренний паддинг карточки и панели |
| `space5` | 18 | зазор между подписью и полем в строке |
| `radiusPanel` | 20 | панель попапа и окна |
| `radiusCard` | 15 | карточка |
| `radiusControl` | 12 | дорожка сегментов, тумблер |
| `radiusPill` | 11 | кнопка-пилюля, поле ввода |
| `radiusTile` | 10 | активный сегмент, иконочная кнопка-плитка |
| `popupWidth` | 352 | ширина попапа менюбара |
| `windowWidth` | 500 | ширина окна настроек |

## Компоненты

### Панель

Контейнер верхнего уровня: попап менюбара и окно настроек. Фон `shell`, граница 1 pt `line`,
радиус `radiusPanel`, паддинг `space4`, тень `panelShadow`.

### Карточка

```
┌─────────────────────────────┐
│ ЦЕЛИ                        │  ← капс, 11 semibold uppercase, faint
│ ChatGPT               3  🗑  │  ← строка
│ приложение · /Applications… │
│ ─────────────────────────── │  ← разделитель 1 pt line
│ qwen                  1  🗑  │
└─────────────────────────────┘
```

Фон `card`, граница 1 pt `line`, радиус `radiusCard`, паддинг `space4`, тень `cardShadow`.
Между карточками `space3`. Капс обязателен — карточка без заголовка не используется.

### Строка

Горизонтальный ряд: название слева, значение и управление справа, вертикальный паддинг `space2`,
зазор `space3`. Соседние строки разделяет линия `line` (первая строка без линии сверху).
Всё содержимое выравнивается по центру строки. Подпись под названием — 12 pt `faint`,
её ставят только там, где без неё не понять объект (путь цели), а не ради красоты.

Строка с полем ввода: подпись, зазор `space5`, поле на всю оставшуюся ширину.

### Сегменты

Дорожка `sunk` с границей `sunkLine`, радиус `radiusControl`, паддинг `space1`.
Сегмент: радиус `radiusTile`, 12 pt medium, неактивный — `dim`, активный — заливка `violet`
и белый текст. Сегменты делят ширину поровну.

Применяются в трёх местах: навигация окна («Настройки», «Журнал»), интервал опроса (5/10/15 с),
выбор темы (Тёмная / Светлая). Больше четырёх пунктов в дорожку не кладём.

### Кнопки

| Тип | Фон | Текст | Когда |
|---|---|---|---|
| Первичная | `violet` | белый | главное действие группы: «Добавить» |
| Приглушённая | `sunk` + граница `line` | `ink` | второстепенное: «Выбрать…» |
| Деструктивная | `red` 16% | `red` | «Удалить приложение…», «Очистить журнал» |
| Плитка-иконка | `violet` | белая иконка | «Проверить обновления»: 30×30, радиус `radiusTile` |
| Иконка без фона | нет | `faint` | удаление строки, шестерёнка попапа |

Радиус пилюль `radiusPill`, паддинг 8 / 15, текст 13 semibold. Кнопки, стоящие в один ряд
внизу карточки, делят ширину поровну.

Нажатие — изменение непрозрачности заливки, без сдвига геометрии. Фокус с клавиатуры —
кольцо `violet` 2 pt. Деструктивное действие всегда подтверждается системным `NSAlert`.

### Поле ввода

Фон `sunk`, граница `sunkLine`, радиус `radiusPill`, паддинг 8 / 11, текст 13 pt `ink`,
подсказка `faint`. Подсказка описывает формат ввода («Код страны (RU), IP или CIDR»), а не
повторяет название пункта. У поля всегда есть видимая подпись слева — плейсхолдер подписью не служит.

### Тумблер

38×22, радиус `radiusControl`, включённый — `violet`, бегунок белый 18 pt.

### Щит статуса

Плитка 32×32, радиус 11, фон — цвет текущего статуса, внутри белая иконка щита 16 pt.
Единственный элемент, меняющий цвет вместе со статусом; рядом обязателен текст статуса
тем же цветом.

| Состояние | Цвет | Заголовок |
|---|---|---|
| Всё в порядке | `green` | На страже |
| Основной источник не ответил | `amber` | Ipinfo недоступен |
| Подтверждающий источник не ответил | `amber` | Ipwhois недоступен |
| Цели завершены | `red` | Цели завершены |

Жёлтый статус называет конкретный сервис, а не пишет «Сервис недоступен».

### Пилюля процесса

Строка живого процесса цели в попапе: иконка 32×32 (та же величина, что у щита), имя цели,
справа число дочерних процессов вида `+3`. Фон `sunk`, граница `sunkLine`, радиус `radiusCard`,
паддинг 6 слева и 12 справа. Пилюли идут одна под другой, каждая во всю ширину панели.

Одна пилюля — один родительский процесс. Потомки не получают собственных строк, они считаются
в `+N`; процесс, чей предок уже в списке, строкой не становится.

Иконку определяет тип цели, а не догадка по имени:

| Тип цели | Иконка |
|---|---|
| `.app`-бандл | иконка приложения из системы (`NSWorkspace.icon(forFile:)`) |
| известный CLI (`claude`, `codex`) | логотип бренда из ресурсов на плитке фирменного цвета |
| прочие бинарники и скрипты | иконка Terminal.app из системы |

Список известных CLI ведётся руками: у Node-скрипта логотипа взять неоткуда. Терминальный
`claude` и приложение ChatGPT не путаются — тип цели известен ещё при разрешении пути.

### Строка данных

Три строки, ключ `faint`, значение `dim`, цифры табличные:

```
IP: 203.0.113.28
ipinfo: KZ
ipwhois: KZ
```

Недоступное значение — короткое тире `—`, неизвестный адрес — «неизвестен». Пустых мест
и прочерков-заглушек другого вида нет.

### Запись журнала

Три строки без плашек, рамок и цвета:

```
ChatGPT                                   ← 13 medium, ink
завершено — обнаружена страна KZ по данным ipinfo   ← 13, dim
27.07.2026 16:49 · IP: 203.0.113.28 · ipinfo: KZ · ipwhois: KZ   ← 11, faint, tabular
```

Причина пишется строчной буквой после действия, кроме аббревиатур («VPN Happ не держит…»).
Диагностическая строка выделяется мышью.

### Кнопки окна

Три круга 12 pt с зазором 6: закрытие — `close`, свёртывание и полноэкранный режим — `ink` 18%
и неактивны. Заголовка и иконки у окна нет, роль заголовка исполняют сегменты навигации.

## Экраны

### Значок в менюбаре

Холст 22×22, круглый флаг страны 16 pt, обводка 1 pt `labelColor` 55%, точка статуса 7 pt
под −45° с вырезом 2 pt. Цвет точки — цвет статуса. Пока страна неизвестна — серый круг-заглушка,
не флаг и не эмодзи.

### Попап менюбара

```
┌──────────────────────────────────┐
│ ▣  На страже                 ⚙︎  │  щит, статус, шестерёнка по центру щита
│                                  │
│ IP: 203.0.113.28                  │
│ ipinfo: KZ                       │
│ ipwhois: KZ                      │
│ ──────────────────────────────── │
│ ▣ ChatGPT                    +3  │  живые процессы целей
│ ▣ claude                     +2  │
└──────────────────────────────────┘
```

Список процессов отвечает на вопрос «можно ли уже выключать VPN». Когда не запущено ничего,
вместо пилюль стоит зелёная строка «Цели не запущены — VPN можно выключать»; когда целей нет
в настройках, раздела нет вовсе.

В попапе нет ни навигации, ни тумблеров, ни журнала: он отвечает на один вопрос — можно ли
сейчас работать. Всё управление живёт в окне настроек.

Тумблера охраны нет нигде: kill switch включён всегда, пока приложение запущено, а выключение —
это «Закрыть приложение» в обслуживании. Переключатель, которым можно снять защиту одним
щелчком, противоречит смыслу инструмента.

### Окно

```
┌─────────────────────────────────────────┐
│ ● ○ ○                                    │  кнопки окна системные
│ ┌─── Настройки ───┬─── Журнал ────────┐  │
│ [        карточки вкладки            ]   │
│ github                 версия 0.1.0  [⟳] │  прокручивается вместе с карточками
└─────────────────────────────────────────┘
```

Вкладка «Настройки»: Цели → Сеть и гео → Чёрный список → Внешний вид → Обслуживание.
Вкладка «Журнал»: записи и «Очистить журнал».

Подвал — последняя строка прокручиваемого содержимого, а не закреплённая полоса: слева
ссылка «github», справа версия и кнопка проверки обновлений. Встать на одну строку
с кнопками окна нельзя — SwiftUI отводит контенту безопасную зону под ними.

Пояснения к вводу живут под карточкой мелким шрифтом, а не в подсказке поля: подсказка
исчезает при первом же символе, а формат ввода нужен именно во время набора.

## Текст

- Заголовки статусов — с заглавной, без точки.
- Кнопка называет действие, а не намерение: «Добавить», «Очистить журнал», «Закрыть приложение».
- Многоточие в конце кнопки означает, что дальше будет подтверждение или диалог выбора.
- Причины в журнале и статусах пишутся от лица системы, без извинений и восклицаний.
- Пустое состояние объясняет, что делать: «Цели не выбраны — охрана ничего не завершает».

## Реализация в SwiftUI

| Компонент системы | Тип в коде |
|---|---|
| Панель | `WetoPanel(width:)` |
| Карточка | `WetoCard("Заголовок") { … }` |
| Строка | `WetoRow { … }`, разделитель — `WetoDivider()` |
| Сегменты | `WetoSegmentedControl(selection:options:)` |
| Кнопки | `WetoPillButtonStyle(.primary / .ghost / .danger, expands:)` |
| Кнопка-плитка | `WetoTileButtonStyle()` |
| Иконка без фона | `WetoIconButtonStyle()` |
| Поле ввода | `WetoFieldStyle()` |
| Щит статуса | `StatusShield(tone:)`, тон — `StatusTone` |
| Пилюля процесса | `WetoProcessPill(icon:title:childCount:)`, иконка — `TargetIconStore` |
| Токены | `WetoTokens`, цвет — `WetoColor.resolve(scheme)` |

- Токены живут в `Sources/WetoDesign/Tokens/`, компоненты — в `Sources/WetoDesign/Components/`.
  Цвет объявляется парой значений (тёмное / светлое) и разрешается по текущей теме.
- Кнопки, делящие ширину поровну, получают `expands: true` у стиля, а не `.frame(maxWidth:)`
  снаружи: внешний фрейм растягивает только зону нажатия, подложка остаётся по размеру текста.
- В экранах не должно быть ни одного `Color(hex:)`, `.font(.system(size:))` или числового радиуса —
  только токены и готовые компоненты.
- Тема хранится в настройках (`SettingsStore.appTheme`) и кладётся в окружение
  через `.environment(\.colorScheme, …)`, откуда её читают компоненты. Одного
  `.preferredColorScheme` мало: попап `MenuBarExtra` его не слушает и остаётся в системной теме.
  Системная тема сознательно не поддерживается, чтобы обе палитры оставались проверяемыми.
- Иконки — SF Symbols (`shield`, `gearshape`, `trash`, `arrow.clockwise`), обычной толщины.
  Эмодзи и растровые иконки не используются.
- Компонент дизайн-системы не обращается к `AppCoordinator` и вообще к состоянию приложения:
  он принимает данные параметрами.
- Изменение внешнего вида начинается с правки этого документа, а не экрана.
