# Ручная проверка интерфейса

Раскладку виджетов и внешний вид автоматика не проверяет: снимочные тесты GTK
стоят дороже, чем ловят. Машинно проверено другое, и это стоит знать, чтобы
не тратить руки на то же самое:

| Проверка | Где |
|---|---|
| Обе таблицы стилей разбираются GTK без единой ошибки | `weto-ui/tests/css.rs` |
| В готовых стилях нет CSS-переменных (пол — GTK 4.14) | там же |
| Темы отличаются и описывают один набор правил | там же |
| Иконка трея рисуется из общего исходника и меняет цвет | `weto-tray/src/icon.rs` |
| Тексты статуса и причин | `weto-core/src/presentation.rs` |
| Приложение поднимается без монитора и без трея, молча | `scripts/tests/app-smoke-contract.sh` |
| Автозапуск — ровно один файл | `weto-sys/tests/autostart.rs` |

Прогон:

```bash
# Дисплей поднимаем сами: xvfb-run в контейнере повисает — стартует Xvfb
# и не запускает команду вовсе.
linux/scripts/dev.sh bash -c "Xvfb :99 -screen 0 1280x1024x24 & sleep 2
                              DISPLAY=:99 cargo test --workspace"
linux/scripts/dev.sh bash scripts/tests/app-smoke-contract.sh
```

## Чеклист на живом рабочем столе

Проходить на четырёх окружениях: **Ubuntu GNOME**, **KDE Plasma**,
**ванильный GNOME без расширений**, **Hyprland с waybar**.

### Трей

- [ ] Иконка видна на панели.
- [ ] Цвет иконки меняется вместе со статусом: зелёный — на страже,
      жёлтый — источник молчит или цели на паузе, красный — цели завершены,
      серый — охрана выключена или ответа ещё нет («Проверяю выход»).
- [ ] Наведение показывает подсказку с заголовком статуса.
- [ ] Левый клик открывает окно статуса.
- [ ] Правый клик даёт меню из трёх пунктов: «Проверить сейчас», «Настройки», «Выход».

**Ванильный GNOME:** трея не будет — это ожидаемо. Проверять здесь надо второй
вход: ярлык в меню приложений и повторный запуск `weto`, который обязан поднять
окно уже работающей копии, а не второй процесс.

### Окно статуса

- [ ] Щит и заголовок читаются за долю секунды и совпадают по цвету.
- [ ] Рядом с цветом всегда есть текст — цвет не единственный носитель смысла.
- [ ] Строки данных показывают IP и обе страны; недоступное значение — короткое тире.
- [ ] Живые цели идут пилюлями, у сеанса с потомками справа `+N`.
- [ ] «Проверить» не подвешивает окно: интерфейс отзывается, пока идёт запрос.
- [ ] В «На страже» и «Охрана выключена» под шапкой нет ни строчки объяснения —
      сразу гео-показания. В «Проверяю выход», «На страже» с жёлтым щитом
      (помехи), «Выход не подтверждён» и «Небезопасно» над показаниями стоят
      три строки: что сделал weto (яркий текст), почему (приглушённее) и что
      дальше (самый тихий).

### Пауза (`Выход не подтверждён`)

Сценарий 3 из `manual-check.md` (`sudo ip link set wg0 down` с целью, например
`nano`, запущенной в терминале) даёт под GTK то же самое, что и `wetod --watch`
в консоли — но теперь ещё и с лицом:

- [ ] Заголовок и щит становятся жёлтыми и говорят «Выход не подтверждён».
- [ ] Третья строка объяснения — отсчёт до потолка, тикающий раз в секунду,
      и число на ней совпадает с числом на пилюле цели с точностью до секунды.
- [ ] У стоящей цели перед `+N` появляется янтарная капсула с отсчётом
      («⏸ 43 с») — тот же цвет и то же число, что в третьей строке.
- [ ] Если цель потеряла терминал (задание ушло в фон), рядом с капсулой
      стоит значок `(i)`, а наведение показывает: «Процесс вернулся в фон.
      Откройте терминал и введите fg». Кнопки «Показать терминал» здесь нет —
      см. «Известные отступления от macOS» ниже.
- [ ] Системное уведомление о потере терминала приходит один раз, а не на
      каждый такт.
- [ ] Туннель поднят обратно до истечения минуты → щит и заголовок
      возвращаются к «На страже», пилюля и её капсула исчезают.
- [ ] Туннель не поднят минуту → «Небезопасно», цель завершена, весь блок
      объяснения и пилюля обновляются на завершение без ручного обновления окна.

### Окно настроек

- [ ] Сегменты «Настройки» / «Журнал» переключают содержимое.
- [ ] Шесть карточек в том же порядке, что на macOS: «Цели», «Сеть и гео»,
      «Чёрный список», «Белый список», «Внешний вид», «Обслуживание», под ними
      подвал.
- [ ] Тумблеры сохраняются: закрыть окно, открыть заново — состояние то же.
- [ ] Добавленная цель появляется в списке и в попапе.
- [ ] Пустой список туннелей сопровождается подсказкой, а не молчанием.
- [ ] Переключение темы перекрашивает оба окна сразу, без перезапуска.

### Поведение

- [ ] Уведомление приходит при завершении целей (если тумблер включён).
- [ ] Автозапуск переживает выход из сессии и вход обратно.
- [ ] Охрана работает, даже если ни одно окно ни разу не открывали.

## Известные отступления от macOS

Их три, все вынужденные, и все стоит держать в голове при проверке:

1. **Попап не привязан к иконке трея.** SNI не сообщает координат иконки,
   Wayland не даёт окну позиционировать себя. Окно статуса открывается там,
   где решит композитор.
2. **Меню трея рисует панель**, а не приложение: дизайн-система на него
   не распространяется, и выглядеть оно будет по-разному в KDE и GNOME.
3. **У значка паузы нет кнопки «Показать терминал».** На macOS она поднимает
   окно терминала через `NSRunningApplication`, поднимаясь от шелла до
   процесса-владельца бандла (`TerminalLocating`). У X11/Wayland такого
   единого API нет, а поднять его можно только внешним инструментом
   (`wmctrl`, `xdotool`), который проект не тянет в зависимости и который
   не гарантированно стоит в системе. Значок `(i)` с текстом подсказки
   остаётся — весь смысл в том, чтобы пользователь понял, что случилось
   и что делать (`fg` в своём терминале), а не в том, чтобы это делал weto.
