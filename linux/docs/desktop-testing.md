# Проверка на живом рабочем столе

Как проверить Linux-версию с Mac — и глазами, и функционально, в одном сеансе.

Машины поднимаются через OrbStack: в его ядре есть WireGuard и `/dev/net/tun`,
поэтому настоящий туннель там создаётся, а не имитируется. Рабочий стол — KDE:
у него StatusNotifierItem родной, без плагинов и расширений, и это одна из двух
целевых сред.

## Подготовка

```bash
linux/scripts/desktop-machine.sh ubuntu:noble weto-ubuntu   # пол GTK 4.14
linux/scripts/desktop-machine.sh arch         weto-arch
```

Скрипт создаёт машину, ставит KDE и зависимости, собирает weto из рабочего дерева
(отдельным каталогом сборки, чтобы не мешать артефактам с Mac), устанавливает его
и поднимает VNC. Дальше с Mac:

```bash
open vnc://weto-ubuntu.orb.local:5901        # пароль: weto
```

Машины намеренно `amd64`: релиз выпускается под x86_64, и проверять надо его.
Переопределяется переменной `WETO_MACHINE_ARCH=arm64`, если нужна скорость.

## Часть первая: глазами

В сеансе KDE запустить `weto` из меню приложений или из терминала.

- [ ] Иконка появилась в трее.
- [ ] Наведение показывает заголовок статуса.
- [ ] Левый клик открывает окно статуса; правый — меню из трёх пунктов.
- [ ] Щит и заголовок совпадают по цвету; рядом с цветом всегда есть текст.
- [ ] Карточки, отступы и капсы совпадают с `docs/design-system.md`.
- [ ] Переключение темы в настройках перекрашивает оба окна сразу.
- [ ] Вкладка «Журнал» показывает записи, диагностическая строка выделяется мышью.

Ванильный GNOME проверяется отдельно и ради одного: **трея там нет**, и приложение
обязано остаться доступным. Ставится `gnome-session` вместо KDE; проверять надо
ярлык в меню приложений и повторный запуск `weto`, который поднимает окно уже
работающей копии, а не второй процесс.

## Часть вторая: функционально

### Туннель и завершение целей

Настроить цель и интерфейс:

```bash
orb -m weto-ubuntu bash
mkdir -p ~/.config/weto && chmod 700 ~/.config/weto
printf '%s' "<токен ipinfo>" > ~/.config/weto/token && chmod 600 ~/.config/weto/token
```

В настройках приложения добавить целью `/usr/bin/nano` и выбрать туннель.
Туннеля пока нет — список пуст, и на это есть подсказка. Создаём:

```bash
orb -m weto-ubuntu -u root bash -c '
  ip link add dev wg0 type wireguard
  ip addr add 10.9.0.2/24 dev wg0
  ip link set wg0 up
'
```

- [ ] `wg0` появился в списке туннелей **без перезапуска приложения**.
- [ ] Выбор `wg0` меняет статус: маршрут через него не идёт, значит «VPN поднят,
      но трафик идёт мимо него», цели завершаются.

Отдаём туннелю маршрут — так же, как это делает `wg-quick`, через свою таблицу:

```bash
orb -m weto-ubuntu -u root bash -c '
  ip route add default dev wg0 table 51820
  ip rule add not fwmark 51820 table 51820 priority 32764
'
```

- [ ] Статус стал «На страже» (гео-проба уйдёт в никуда через мёртвый туннель —
      для проверки самой логики маршрута достаточно, что охрана видит владельца).
- [ ] Запущенный `nano` виден пилюлей в окне статуса.

Роняем туннель:

```bash
orb -m weto-ubuntu -u root ip link set wg0 down
```

- [ ] `nano` завершился меньше чем за секунду.
- [ ] Пришло уведомление о завершении.
- [ ] В журнале появилась запись с причиной «VPN не поднят».

### Скриптовая цель

```bash
orb -m weto-ubuntu bash -c 'readlink -f "$(command -v npx)"'
```

Вписать полученный путь целью, запустить `npx`, уронить туннель.

- [ ] `npx` завершился, хотя `/proc/<pid>/exe` указывает на `node`.
- [ ] Другие процессы `node` живы.

### Обновление

Настоящий релиз для этого не нужен: локальный сервер отдаёт ответ в той же форме,
что GitHub. Окно для него открывается только в отладочной сборке — в релизной
обе переменные не читаются вовсе, ветку вырезает `cfg`.

```bash
orb -m weto-ubuntu bash -lc '
  cd /Users/<вы>/Documents/projects/samples/weto/linux
  CARGO_TARGET_DIR=$HOME/weto-target scripts/fake-release.sh 9.9.9
'
```

Во втором терминале машины:

```bash
WETO_TEST_RELEASE_API=http://127.0.0.1:8765/release.json \
WETO_TEST_RELEASE_ORIGIN=http://127.0.0.1:8765/ \
  ~/weto-target/debug/weto
```

- [ ] В окне статуса появился баннер «Доступно обновление 9.9.9».
- [ ] Кнопка открывает окно с версией и заметками релиза.
- [ ] «Позже» прячет баннер; после перезапуска он не возвращается (отсрочка час).
- [ ] «Пропустить эту версию» прячет её насовсем; «Проверить обновления»
      в настройках возвращает.
- [ ] «Обновить» показывает шкалу, приложение перезапускается само,
      а `weto --version` сообщает 9.9.9.

### Откат

Подложить в новую версию заведомо нерабочий бинарник и запустить дважды:

```bash
orb -m weto-ubuntu bash -c '
  printf "#!/bin/sh\nexit 1\n" > ~/.local/share/weto/9.9.9/bin/weto
  chmod +x ~/.local/share/weto/9.9.9/bin/weto
  weto; weto; readlink ~/.local/share/weto/current
'
```

- [ ] `current` вернулся на предыдущую версию.

### Установка и удаление

```bash
orb -m weto-ubuntu bash -c '~/.local/share/weto/current/share/uninstall.sh; find ~ -name "*weto*" | head'
```

- [ ] После удаления не осталось ни одного файла weto.

## Чего эти машины не покажут

**Wayland.** Сеанс идёт через VNC, то есть по X11. Единственное отступление
от macOS — окно статуса не привязано к иконке трея, потому что SNI не сообщает
координат, — на X11 выглядит иначе, чем на Wayland. Проверять это имеет смысл
только в настоящей VM с Ubuntu Desktop, и поведение там известно заранее:
место окна выбирает композитор, повлиять на это нечем.
