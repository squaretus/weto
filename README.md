# weto

Приложение в менюбаре macOS, которое завершает процессы выбранных приложений и команд,
как только компьютер перестаёт выходить в сеть через корпоративный VPN.

Задача прикладная: корпоративные приложения допустимо использовать только из корпоративной
сети, а доступ с постороннего адреса служба безопасности расценивает как инцидент.
Цена ложного срабатывания (приложение закрыто зря) несопоставимо ниже цены пропуска
(ушёл запрос с чужого адреса), поэтому вся логика построена по принципу fail-closed:
любая неопределённость трактуется как опасность.

## Как это работает

Три уровня проверок, от самого быстрого к самому медленному:

1. **VPN.** Выбранный сетевой сервис должен быть поднят **и** держать default route.
   Читается из `SCDynamicStore` мгновенно и без обращения к сети — самый частый сценарий
   (упал туннель) отрабатывает за доли секунды.
2. **Гео.** Внешний адрес запрашивается у `ipinfo`, страна этого адреса подтверждается
   вторым сервисом. Заблокированные страны настраиваются, по умолчанию `RU`.
3. **Чёрный список.** Конкретные адреса и подсети, с которых работать нельзя.

Не сошлось хоть что-то — процессы целей завершаются по `SIGKILL` вместе с потомками,
а попытки запустить их заново пресекаются, пока состояние небезопасно.

## Цели

Одним списком: приложения (`.app` или bundle ID), бинарники (`/usr/bin/curl`) и команды
терминала (`nano`). Разрешение цели учитывает две ловушки:

- `/usr/bin/nano` — симлинк на `pico`, и ядро сообщает именно `pico`;
- у скрипта с shebang (`qwen` — Node) `proc_pidpath` указывает на интерпретатор,
  поэтому такие цели ищутся по командной строке, а не по пути.

## Запуск

```bash
swift build                # сборка
swift test                 # тесты
scripts/make-app.sh release  # .app-бандл → .build/app/Weto.app
```

Автозапуск включается тумблером в настройках — ставится пользовательский LaunchAgent
с `KeepAlive`, чтобы падение приложения не означало потерю защиты.

## Устройство

| Модуль | Назначение |
|---|---|
| `WetoCore` | чистая логика решения, ноль обращений к системе |
| `WetoSystem` | границы системы за протоколами: сеть, гео, процессы, Keychain |
| `WetoShared` | VM-слой `@Observable @MainActor` |
| `WetoDesign` | токены и компоненты оформления |
| `WetoMenuBar` | `MenuBarExtra` и окно настроек |

`WetoCore` не импортирует `Network`, `SystemConfiguration`, `AppKit` и не использует
`URLSession`. Инвариант держит основную массу тестов синхронной и свободной от моков;
подменяются только границы системы.

Дизайн и обоснования решений — `docs/superpowers/specs/`, план реализации — `docs/superpowers/plans/`.

## Чего приложение не делает

Не блокирует сетевые пакеты. Настоящая пофлоу-фильтрация на macOS требует
`NEFilterDataProvider`, а он — энтайтлмента по заявке в Apple, платного Developer ID
и системного расширения. Завершение процессов даёт сопоставимую гарантию несравнимо дешевле.
